# NestJS Core Architecture & Standards

You are acting as a Principal NestJS Architect. Follow these rules whenever writing or modifying NestJS backend code.

> **Mandatory Skill Chain:** Whenever creating or modifying HTTP endpoints, controllers, DTOs, or responses, you **MUST** also read and enforce [api-contract](../api-contract/SKILL.md) and [api-contract/examples/nestjs.md](../api-contract/examples/nestjs.md).

## 1. Step 0: Detect Project Topology (Solo Repo vs. Monorepo)

Inspect the workspace root (`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `nx.json`, `apps/`, `packages/`) before creating files:

### Approach A: Standalone / Solo NestJS Project
```text
├── drizzle.config.ts
└── src/
    ├── common/                  # decorators/, filters/, guards/, http/, interceptors/, middleware/, pipes/
    ├── config/                  # Typed @nestjs/config + Zod env validation
    ├── db/
    │   ├── migrations/          # SQL migrations generated by drizzle-kit
    │   ├── schema/              # One file per table + index.ts barrel file
    │   └── db.module.ts         # Global Drizzle Pool + DB_PROVIDER token
    ├── jobs/                    # BullMQ processors & @nestjs/schedule cron jobs
    └── modules/<feature>/       # dto/, controller, service, module
```

### Approach B: Monorepo (`apps/api` + Shared `packages/`)
```text
├── apps/api/src/                # common/, config/, db/ (wraps @repo/db), jobs/, modules/<feature>/
└── packages/
    ├── db/                      # @repo/db: drizzle.config.ts, migrations/, src/client.ts, src/schema/index.ts
    └── types/                   # @repo/types: shared Zod schemas, DTO types & ApiResponse<T>
```
- **Monorepo Rules:** Never duplicate schemas or DTOs inside `apps/api`. Import tables and Drizzle operators (`eq`, `and`, `sql`) from `@repo/db`, and shared Zod schemas/DTOs from `@repo/types`.

## 2. Database Schema & Migrations Standard

1. **`schema/` with `index.ts` Barrel File:**
   - One file per domain table (`users.schema.ts`, `orders.schema.ts`).
   - Re-export all tables and relations from `schema/index.ts` and pass that barrel to `drizzle(pool, { schema })`.
   - Export inferred row types (`typeof users.$inferSelect`, `typeof users.$inferInsert`).
2. **`migrations/` Directory:**
   - Point `drizzle.config.ts` to `schema/index.ts` and output SQL migrations to `migrations/`. Never hand-edit generated SQL files.
3. **Async/Await & Transactions:**
   - Use `async/await` for all DB calls (no `.then()` chains). Use `await Promise.all([...])` only for independent parallel reads.
   - Wrap multi-table writes in `await this.db.transaction(async (tx) => { ... })`.

## 3. Middleware, External Auth Guards & Decorators

1. **Middleware (`src/common/middleware/`):**
   - Runs before routing/guards. Use only for correlation IDs (`X-Request-Id`), request logging, and raw webhook body parsing (`rawBody: true` for Clerk/Stripe signature verification).
2. **External Auth Provider Guard (`src/common/guards/`):**
   - Verify external tokens (Clerk / Supabase Auth / Auth0 SDK) inside `ExternalAuthGuard`.
   - Attach verified claims (`sub` as `externalId`, `email`, `role`) to `req.user`.
   - Register globally via `APP_GUARD` and opt out public/webhook routes with `@Public()`.
   - Sync external users into the local Drizzle `users` table via a signed Webhook endpoint (`user.created` / `user.updated`) with an idempotent `onConflictDoUpdate` upsert fallback.
3. **Built-in & Custom Decorators (`src/common/decorators/`):**
   - Use `@Public()` and `@Roles(...roles)` (`SetMetadata`) read via `Reflector`.
   - Use `@CurrentUser()` (`createParamDecorator`) to extract typed `AuthUser` instead of injecting `@Req()`.
   - Use composed `@Auth(...roles)` (`applyDecorators`) to combine `@Roles()` + `@UseGuards()`.

## 4. Two-Tier Async Jobs, Rate Limiting, Caching & Ops

1. **Two-Tier Async Processing:**
   - **Tier 1 (`@nestjs/event-emitter`):** Fast, non-critical in-process side effects (audit logs, cache invalidation).
   - **Tier 2 (`@nestjs/bullmq` + Redis):** Heavy or external tasks (emails, webhooks, AI, exports, PDFs). Always configure `attempts`, exponential `backoff`, and deterministic `jobId` for idempotency.
   - **Scheduled Jobs (`@nestjs/schedule`):** Use `@Cron()` in dedicated worker services; prevent overlapping runs on multi-instance deployments with a Redis lock or BullMQ repeatable job.
2. **Rate Limiting & Redis Cache-Aside:**
   - Enable `@nestjs/throttler` globally (`ThrottlerGuard`) and apply stricter `@Throttle()` limits on public, auth, and webhook endpoints.
   - Use explicit Redis **cache-aside** in services (`get` -> DB fallback -> `set` with TTL) and explicitly invalidate keys (`del`) on `POST`/`PATCH`/`DELETE` mutations.
3. **Logging, Security Hardening & Health Check:**
   - **Never use `console.log`.** Always use Nest `Logger` (`private readonly logger = new Logger(ClassName.name)`) or `nestjs-pino` with correlation IDs.
   - In `main.ts`, always enable `helmet()`, strict `app.enableCors()`, `app.enableShutdownHooks()`, and global `ApiExceptionFilter`.
   - Expose a `@Public() @Get('health')` readiness endpoint that pings both Drizzle (`SELECT 1`) and Redis (`PING`).
